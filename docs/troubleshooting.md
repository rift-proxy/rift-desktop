# Если не работает

Посмотрите версию в «Настройки» -> «О приложении» и сообщения в «Журнал». Не удаляйте `data` ради проверки: там серверы и настройки.

## Подключено, браузер идёт напрямую

В Proxy укажите в браузере HTTP/SOCKS5-адрес из Rift. По умолчанию это `127.0.0.1:2080`, но порт мог измениться. Системный прокси Windows Rift не включает.

В TUN локальный прокси выключен. Если нужны оба способа, выберите «TUN + Proxy». Проверьте `Direct` и порядок списков в [маршрутизации](usage.md#маршрутизация): правила могут направлять трафик мимо сервера.

## Отказали UAC, TUN не включился

Rift сохранил режим Proxy. Настройте прокси в приложении либо заново выберите TUN или TUN + Proxy в «Настройки» -> «Режим работы» и подключитесь, подтвердив запуск доверенного помощника. Просто повторить подключение недостаточно: без смены режима UAC не появится.

Постоянно запускать весь интерфейс от администратора не нужно. Если помощник завершился с ошибкой, сохраните код из журнала и [сообщите о сбое](#сообщить-о-сбое).

## Не ставится WebView2

Проверьте доступ к сайту Microsoft и ограничения организации. Без WebView2 интерфейс не работает; при отсутствии Runtime установщик скачивает Evergreen bootstrapper. Офлайн-runtime в пакет Rift не входит.

При необходимости установите Runtime с [официальной страницы Microsoft](https://developer.microsoft.com/microsoft-edge/webview2/), затем повторите установку Rift. Не отключайте Defender или SmartScreen.

## Подписка не обновляется

1. Обновите нужную подписку в «Серверах» и посмотрите причину в «Журнал», источник «Подписки».
2. Уточните у провайдера срок действия, лимит трафика и актуальность ссылки. Нужен HTTPS URL без логина и пароля в адресной части. Не публикуйте URL: путь или query могут содержать токен.
3. При `subscription_timeout` или `subscription_transport` проверьте сеть и доступность сервиса. `subscription_http_status` означает HTTP-ошибку провайдера; для обращения хватит статуса и кода, без тела ответа.
4. При `subscription_invalid_body` уточните формат у провайдера. При `subscription_filtered` ослабьте фильтры названий/протоколов и обновите снова. Не заменяйте HTTPS на HTTP и не отключайте проверку TLS.

Не удаляйте рабочую подписку из-за ошибки обновления: прежние серверы сохраняются. Если срок подписки истёк или трафик исчерпан, её серверы исключаются из автовыбора.

## Сервер доступен, интернета нет

«До сервера» проверяет доступность адреса сервера, «Через сервер» проверяет доступ через него. Выберите другой сервер, нажмите «Проверить сейчас», проверьте маршрутизацию. Для автоматического переключения включите «Автовыбор сервера»; ручной выбор его не отключает.

При «Локальный порт уже занят» выберите свободный порт прокси в настройках. Не завершайте незнакомые процессы по имени.

## Обновление не предлагается или не ставится

Нажмите «Настройки» -> «Проверить обновления». Сборка могла быть без встроенного адреса обновлений; отклонённая версия не предлагается до перезапуска. Проверьте [официальные выпуски](https://github.com/rift-proxy/rift-desktop/releases): черновик (draft) обычному updater недоступен.

При сетевой ошибке повторите позже. При ошибке подписи не отключайте проверку и не запускайте отвергнутый файл. Сверьте версию и источник, сообщите о сбое. Ошибка скачивания или подписи не останавливает текущее соединение. Если установщик не запустился после остановки ядер, перезапустите Rift.

### SmartScreen и Authenticode

Minisign-подпись `.sig` проверяет обновление Rift по встроенному ключу. Authenticode подписывает файл от имени издателя Windows; текущий release workflow её не делает. SmartScreen учитывает репутацию файла и издателя, которую minisign не создаёт.

При предупреждении проверьте источник загрузки и подпись в свойствах файла. При сомнениях остановитесь и передайте сведения через форму. Не отключайте защиту Windows и не обходите проверку подписи обновления.

## Сообщить о сбое

В [форме](https://tally.so/r/per2zq) укажите версию Rift, Windows и её сборку, режим Proxy/TUN/TUN + Proxy, шаги, ожидаемое и фактическое поведение, время сбоя и код из журнала.

При необходимости выберите «Журнал и диагностика» -> «Экспорт диагностики». Файл `data/diagnostics.json` не отправляется сам. Проверьте его перед передачей; обрежьте скриншоты с адресами и личными данными. Не отправляйте профиль, `state.json`, всю `data`, URI серверов, ссылки подписок, пароли или токены. Подробнее о [содержимом диагностики](privacy.md).

Уязвимость не публикуйте в issue: [порядок сообщения](../SECURITY.md).
